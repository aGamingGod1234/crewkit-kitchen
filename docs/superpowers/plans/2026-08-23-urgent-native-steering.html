Implementation

1
App-server boundary

Add a strict turn/steer request using the active thread and expected turn ID. Reject stale revisions and non-native sessions.

2
Warmup takeover

When a real event arrives during observation-only prewarm, replace the restricted executor, steer the event into that turn, and return the same turn result. Do not wait for prewarm to finish.

3
Urgent coordinator path

Steer urgent native events into active work. Coalesce ordinary observations. If steering fails because the turn already ended or cannot accept input, retain one merged pending event.

4
Continuous body proof

Prove an active Minecraft action is not cancelled by urgent steering and that its factual result still returns to the same model turn.

5
Performance proof

Run focused red-green tests, the full coordinator and Java suites, rebuild the JAR, then measure urgent takeover with the authenticated provider and simulated body.

Verified result

✓
Regression evidence

634 coordinator tests, 6,416 core assertions, and 77 voice assertions passed. The production JAR rebuilt successfully.

✓
Live protocol evidence

Authenticated Luna low and Luna xhigh runs both accepted same-turn steering in 1 ms. One thread and one turn were preserved, and the active body command was not cancelled.

!
Measured boundary

The model cannot issue another tool while the previous tool result is pending. With a deliberately held 10-second body result, the steered chat arrived at 11.939 s on low and 14.198 s on xhigh. The next performance change should decouple long-running body completion from the model tool response.

Failure policy

A stale or unsupported steer never drops the event. The coordinator queues the newest merged urgent input for the next turn. Goal revision changes still cancel obsolete model and body work because they represent an explicit new intent.
