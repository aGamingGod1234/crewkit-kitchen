Player-like agents with private DMs and spatial voice

Build near-complete server-side player control, private agent communication visible to operators, and proximity voice where agents and humans hear one another. Fish Audio's free TTS endpoint is the first provider.

Goal and scope

Agents should perform the meaningful actions a real player can perform, communicate privately, speak with stable identities, and react to nearby human speech. The server remains authoritative. Model-authored actions stay bounded and validated.

Execution rule. Use superpowers:subagent-driven-development or superpowers:executing-plans when this plan is implemented. Each task has its own review and test gate. Shared files have one owner at a time.

Included

  • Agent-to-agent and player-to-agent DMs, with an exact-once mirror to every authorized online operator.
  • Separate conversational messages and steering commands. Ordinary DMs never cancel work.
  • Proximity voice through an optional Simple Voice Chat addon.
  • Fish Audio s2.1-pro-free TTS behind a provider interface.
  • One distinct, persistent synthetic voice profile per agent.
  • One realtime STT stream per speaking human UUID, then server-side range fan-out to nearby agents.
  • A complete input-state engine plus targeted interaction and vanilla menu coverage.
  • Focused tests, one live conformance fixture, and a physical 16-agent soak.

Not included in the first release

  • Sixteen real or headless Minecraft clients in production.
  • Offline DM delivery, group channels, call recording, or durable transcript history.
  • Arbitrary packets exposed to models or generic support for unknown modded menus.
  • Celebrity, streamer, or unlicensed human voice cloning.

Architecture

Core Arena Agents owns gameplay, permissions, conversation routing, bounded metadata, and a provider-neutral voice interface. A separate Fabric addon owns Simple Voice Chat. The coordinator hosts a loopback-only voice service that calls Fish Audio and later Deepgram. Raw audio never enters the existing JSONL bridge.

1. IntentThe model chooses public text, direct text, proximity speech, or a gameplay action.
2. AuthorityThe server validates recipient, range, permission, goal revision, target provenance, and current action ownership.
3. DeliveryText uses the conversation router. Audio uses the optional voice addon and the loopback binary HTTP or WebSocket service.
4. MemoryEach agent receives only bounded direct or nearby conversation events. Public facts remain separate.
Human microphone
  -> Simple Voice Chat MicrophonePacketEvent
  -> one Opus/STT stream for that human UUID
  -> final transcript returned to the server
  -> dimension and distance filter
  -> nearby agent conversation memories

Agent speak(text)
  -> text routed directly to nearby agents
  -> Fish Audio s2.1-pro-free generates PCM once
  -> resample to 48 kHz mono
  -> EntityAudioChannel plays to nearby humans

Task 1. Add native DMs and the operator mirror

Agents and players can exchange direct messages. Every authorized operator sees one mirrored copy. Public chat remains backward compatible.

Contract

enum ConversationAudience { PUBLIC, DIRECT, PROXIMITY }
enum ConversationKind { AGENT_MESSAGE, PLAYER_MESSAGE, PLAYER_STEER, PROXIMITY_SPEECH }

record ConversationEvent(
  AgentId agentId,
  String sourceId,
  String recipientId,
  ConversationAudience audience,
  ConversationKind kind,
  String text,
  long goalRevision,
  long observedAtEpochMs,
  long sequence
) {}

interface AgentConversationRouter {
  DeliveryReceipt deliver(ConversationEvent event);
}

Files

Create server/conversation/* and AgentConversationRouterVerification.java. Modify ServerActionExecutor.java, ProtocolCodec.java, CodexAgentCommands.java, GoalControl.java, constants.mjs, schema.mjs, and minecraft-api.mjs.

  • Write failing tests for direct recipient delivery, operator mirroring, deduplication, offline failure, dimension/range filtering, and 512-code-point truncation.
  • Extend player.chat with audience and optional authoritative recipientId. Keep PUBLIC as the omitted default.
  • Add /codex dm <agent> <message>. Add vanilla /msg integration only after the native route passes tests.
  • Route direct messages to the recipient plus every online player accepted by GoalControl.mayControl. Never use AgentChatReporter.report for the mirror.
  • Keep player_message conversational. Keep player_steer on the existing lifecycle reducer so it increments the goal revision exactly once.

Gate: public messages, direct messages, and steering pass exact-once tests, and no DM enters spectator or scenario output.

Task 6. Connect Fish Audio's free TTS endpoint

An agent can choose to speak, and nearby players hear its assigned Fish voice at the entity's position.

Provider interface

interface TtsProvider {
  synthesize({ text, voiceId, signal }): Promise<PcmStream>;
}

type PcmStream = {
  sampleRateHz: 44100;
  channels: 1;
  sampleFormat: "s16le";
  body: AsyncIterable<Uint8Array>;
};

Files

Create coordinator/src/voice/voice-http-server.mjs, fish-tts-provider.mjs, tts-cache.mjs, addon VoiceWorkerClient.java, and focused Node and Java tests.

  • Bind the voice service to loopback only on a dedicated port. Require bearer authentication sourced from a secret file, never a client payload.
  • Call Fish POST /v1/tts with model s2.1-pro-free, format: pcm, sample_rate: 44100, mono output, and the agent's reference_id.
  • Stream binary PCM outside the JSONL bridge. Resample 44.1 kHz to 48 kHz and feed 960-sample, 20 ms frames to Simple Voice Chat.
  • Cap synthesis at five concurrent requests, one active utterance per agent, 280 code points per utterance, and 20 seconds of playback.
  • Cache immutable output by provider, model, voice ID, profile revision, normalized text, prosody, format, and sample rate.
  • Handle timeout, cancellation, rate limit, malformed audio, worker exit, agent death, and addon removal. Text behavior must continue.

Gate: no API key or PCM appears in JSON bridge logs, traces, client payloads, or saved agent data.

Risks and controls

  • Fish's free tier can change. Keep TtsProvider provider-neutral, record usage, cache audio, and keep ElevenLabs as a configuration-only fallback.
  • Simple Voice Chat is an external dependency. Ship the integration as a separate addon and do not bundle its All Rights Reserved mod.
  • Client installation and UDP configuration can fail. Detect capability, expose status to operators, document UDP 24454, and fall back to proximity text.
  • Speech is prompt-injection input. Quote it as untrusted conversation data and keep lifecycle control in explicit commands.
  • Sixteen voices can become noise. Limit utterance length, active speakers, cooldowns, and overlap. Agents should speak only when another player would find it useful.
  • Observation work already risks tick time. Optimize and instrument it before treating the 16-agent soak as passed.
  • Voice cloning has consent and licensing risk. Use synthetic-designed voices and store provenance with each profile.
