Implementation sequence

Specify the boundary

Add strict, provider-neutral tool schemas and bounded result payloads. Invalid names, arguments, revisions, and oversized outputs fail at the coordinator boundary.

Prove the app-server handshake

Add a failing transport test for server-initiated item/tool/call, then implement JSON-RPC request recognition and client responses.

Create the lean Codex thread

Replace the long planner prompt and output schema with a short real-time bootstrap and seven Minecraft tools. The validated act tool retains crafting, building, combat, inventory, interaction, equipment, movement composites, and respawning. Keep the chosen model, effort, and tier unchanged.

Execute while the turn is live

Route each tool request to an injected body executor immediately, return its factual result into the same turn, and allow the model to issue its next action without a new cold thread.

Connect to the existing body

Map tool calls to current bridge actions, correlate action results by ID and goal revision, and feed compact observations and DM events into the persistent agent session.

Preserve lifecycle correctness

Cancel stale calls on steer, death, disconnect, or replacement. Keep provider identity immutable and never switch to another model or hidden decision system.

Measure the real latency

Record provider request, first tool call, bridge dispatch, first progress, completion, and next tool call separately. Remove the existing fake first-byte timestamps.

Verify and roll out

Run focused unit and simulator tests, build the mod, then compare first-action and multi-action latency against the recorded baseline before enabling the new protocol by default.

Decisions

  • No hybrid brain or automatic strategic fallback.
  • No repository, shell, browser, skills, or connector tools in agent threads.
  • Pathfinding and motor timing belong to the body. Goal choice and recovery belong to the selected brain.

Risks and controls

  • Experimental app-server API: isolate it behind one adapter.
  • Stale action results: require turn, action, agent, and goal correlation.
  • Provider variance: compare medians and tails across repeated identical scenarios.

Verified result

  • Warm first tool: 1.7 seconds on Luna low and 1.9 seconds on Luna xhigh in the single-agent authenticated probe.
  • Sixteen concurrent agents reached warm first-tool p50 of 1.410 seconds on low and 1.998 seconds on xhigh.
  • Dependent move then mine calls ran inside one live provider turn.
  • Advanced craft calls passed through the real app-server tool protocol.
  • 622 coordinator tests, 6,416 Java protocol and bridge assertions, and 77 voice-addon assertions passed.
