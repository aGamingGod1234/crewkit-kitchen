Arena Agents · implementation plan

Minecraft decides when an agent is done

Build immutable goal rules inside the mod, reject weak model claims, keep unfinished agents moving, and recover automatically after idle turns, danger, and death.

Status: ready for execution choice8 testable tasksDate: 27 August 2026

Outcome

Authoritative completion

Only live Minecraft state can satisfy a frozen goal rule.

Persistent work

An unfinished goal always owns active work or a deadline-bound next decision.

Honest feedback

A stone pickaxe cannot satisfy an iron-pickaxe request. The agent receives the exact mismatch.

Automatic recovery

Death, respawn, provider failure, and turn completion preserve and resume the same objective.

Execution baseline

Implementation must use a clean worktree based on origin/codex/fix-coordinator-auth-and-console-navigation. The stale dirty root checkout and the existing dirty deployment worktree remain untouched.

Deployment and device updates are a separate gate after reconciliation and full testing.

Task sequence

1

Persist immutable GoalSpec

Add the closed predicate hierarchy, goal status, evidence, fingerprinting, strict codec, and backward-safe snapshot migration.

2

Compile exact requests

Recognize exact items, coordinates, entities, and advancements. Persist ambiguous drafts without interrupting current work.

3

Constrained proposals

Add bounded coordinator translation for complex requests. Every model proposal returns to Minecraft and requires player confirmation.

4

Verify live Minecraft state

Evaluate inventory, stable position, blocks, advancements, survival time, operator confirmation, and agent-specific kills every server tick.

5

Remove model completion authority

Simplify finish to a verification request. Reject false claims and continue the same turn or schedule another.

6

Enforce work leases

Give provider, action, wait, recovery, and scheduled work deadlines. Recover within 2 seconds when no valid work remains.

7

Safety and clarification UX

Add bounded survival reflexes, requester-authorized confirmation commands, concise normal chat, and deduplicated verbose reporting.

8

Headless proof

Replay Sol's false finish and 232-second inactivity pattern, test dragon attribution and death recovery, then run one live iron-pickaxe acceptance task.

Key interfaces

GoalSpec

Original request, closed predicate, creation tick, and immutable fingerprint.

GoalVerificationRuntime

Evaluates the assigned player's live state and records the first accepted evidence.

finish({summary})

Requests verification. It cannot send predicates or a terminal status.

WorkLeaseSupervisor

Tracks deadline-bound work and forces recovery when an unfinished goal loses all valid leases.

Acceptance checks

  1. Stone does not satisfy iron. Iron completes immediately from inventory state.
  2. A false finish leaves the goal active and starts another decision automatically.
  3. Another player killing the dragon does not complete Sol's goal.
  4. Death and respawn keep the exact goal revision and resume without speech.
  5. Ambiguous requests ask Replace / Queue / Cancel while current work continues.
  6. Save and reload preserve active, queued, recovering, and clarification-pending goals.
  7. The captured Sol replay has no unexplained idle gap beyond the 2-second lease.
