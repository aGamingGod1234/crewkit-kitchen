Implementation plan · approved design

Agents that keep going

Replace fragile ArenaScript defaults with native Minecraft tools and make unfinished goals survive turn endings, timeouts, blocked actions, reconnects, death, and other recoverable faults.

Ready to execute

Outcome

For every active goal revision, provider work, a physical action, completion verification, a pending observation, or one scheduled recovery must exist until Minecraft verifies completion or an explicit terminal event occurs.

Recover automatically

Provider failures, empty turns, timeouts, blocked paths, missing drops, bridge loss, death, and rejected completion.

Stop deliberately

Verified completion, explicit stop or replacement, unrecoverable death, validated configuration failure, or shutdown.

Key decisions

  • One event-driven ActiveGoalSupervisor owns liveness policy.
  • Recovery begins at 250 ms, doubles, and caps at 5 seconds.
  • Agent ID, goal revision, and lifecycle generation fence every callback.
  • Legacy preserved config defaults to native_tools.
  • All Codex agents share one static instruction directory under a read-only sandbox.
  • Minecraft remains the only authority allowed to verify completion.
  • Expected bridge refusal is coalesced; logs rotate at 8 MiB with three generations.

Execution sequence

1

Native default and shared workspace

Make the correct runtime unavoidable

Add bundled AGENTS.md and minecraft-control/SKILL.md, refresh them atomically into one shared directory, register the skill root, and start every native thread with sandbox: read-only.

  • Legacy config migration test
  • Atomic and idempotent refresh test
  • Two-agent identical workspace test
2

Supervisor core

Encode the liveness invariant once

Create a deep lifecycle module with provider, action, and completion tokens, one observation lease, exponential backoff, suspension, termination, and stale-revision no-ops.

  • Overlapping provider/action work
  • One timer per revision
  • Backoff reset on progress
  • Close and cancellation cleanup
3

Coordinator integration

Continue after every native turn exit

Move lifecycle policy out of AgentPlanner. Track each provider turn and Minecraft operation, re-observe after successful or empty turns, retry recoverable failures, and reserve agent_error for validated terminal configuration faults.

  • Zero-tool and one-action turns
  • Provider timeout and open circuit
  • Blocked path and action timeout
  • Rejected completion continues
4

Lifecycle alignment

Preserve intent across reconnect and death

Normalize interrupted work to DISCONNECTED, preserve explicit PAUSED, resume exactly once after authenticated reconciliation, and route death/respawn through native events and a new revision.

  • Explicit pause never auto-resumes
  • Disconnect resumes once
  • Death/respawn continues goal
  • Terminal Java/coordinator state matches
5

Bounded diagnostics

Keep useful logs without runaway files

Log the first expected connection refusal, count repeats, summarize recovery, retain structured unexpected stacks, rotate stdout/stderr, and complete owned-process reaping and cleanup.

  • 100 refusals produce two lines
  • Three log generations maximum
  • Unrelated PIDs are never killed
  • No child survives shutdown
6

Fault matrix

Prove the bad paths, not just the happy path

Run the real coordinator against fake external provider/socket boundaries. Cover empty turns, provider failure, action failure, moved drops, completion retries, disconnect, pause, stale revisions, death, repeated failures, and shutdown.

  • Five-plus-turn wooden pickaxe scenario
  • Injected path, provider, drop, and bridge faults
  • No recoverable ERROR or PAUSED
  • One recovery handle maximum
7

Verification and deployment

Ship the exact tested bytes

Run every Node, Gradle, voice-addon, injected-fault, and real headless test; build the release JAR; verify rollback-safe installation; then copy the identical hash to each reachable configured Minecraft device without launching the game.

Completion gate

Runtime

  • Native tools selected after legacy update
  • Identical shared instruction workspace
  • Automatic continuation across every recoverable exit
  • Explicit pause and stale revision safety

Operations

  • Bounded diagnostics and rotated logs
  • No orphan coordinator process
  • All test suites and headless scenario pass
  • Installed hashes match the tested JAR

Risks and controls

Hot recovery loops

One handle per revision plus capped backoff and progress reset.

Stale actions

Agent, revision, and lifecycle-generation fences before every callback.

False completion

Only Minecraft's completion contract verifier may terminate successfully.

Fleet mismatch

Rollback copy, no mutation while Minecraft runs, and SHA-256 equality per device.

Excluded: UI redesign, MCP, shell CLI, non-Codex protocol redesign, and hidden reasoning output.
