# Performance and reliability follow-up

The [19-finding review](https://crjs6rfksbk8.postplan.dev/) examined PR #42 at `5f9db6dd65d7d1cbfe5dc05c859ab214f49c2aba`. Eight bounded verification groups confirmed all 19 findings using source traces, controlled reproductions and negative controls. Eight implementation groups supplied scoped corrections. Root reviewed their changes and integrated the regression tests. These F01–F19 identifiers are separate from the earlier 144-finding disposition record.

The changes recover pending conversations without another player message, retain cancellation and delivery ownership through asynchronous work, and make benchmark completion evidence more trustworthy. They preserve the configured model/profile, the 900-second native cap and the delta-off default.

## Scope and limits

- Newly admitted wakes retain the replay receipt. Receipts already discarded by older code cannot be reconstructed retrospectively. Existing v1 indexes remain readable. This does not establish power-loss durability.
- Auth cancellation safety is per workspace instance. It does not make two files atomically commit across a process crash or genuine disk error.
- Paired receipt v2 certifies `BEFORE_CERTIFICATION_COMMIT`. All lifecycle work and earlier required persistence consume the budget; the final certification-only write is explicitly uncharged. It does not certify its own persistence completion within the budget. Parent, relay and runner must deploy together.
- Linux focused checks use the Unix provider on a mounted Windows filesystem. An additional full-core attempt using the fresh Windows-built classes and exported Gradle classpath could not finish because that cached classpath contains only Windows LWJGL natives. It is not a passing Linux integration run. The clean Ubuntu CI job remains required. Backend fixtures and builds do not prove installed UI behavior or live gameplay.
- No additional live provider/game evaluation was run. Token cost, model quality and diamond-pickaxe/endgame success remain unproven. The earlier 2.079% optimistic response-byte replay reduction, and zero conservative reduction, are not token or dollar measurements.
- The earlier [memory migration, snapshot and other qualifications](performance-reliability-review.md#compatibility-and-remaining-limits) remain applicable. This follow-up closes the 19 reported scopes; it does not erase those separate limitations.

Generated binaries, machine-specific audit logs, provider captures and credentials remain outside the PR.
