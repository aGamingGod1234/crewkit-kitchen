Verdict

The core is stronger than its rough edges suggest. Protocol bounds, signed local bridges, lifecycle recovery, observation budgets, voice consent, archive containment, and the test suite are substantial. The next release should still wait for six issues: the offline gameplay listener, a reconnect lock-order deadlock, missing durable journals around actions and arena preparation, destructive arena placement without preflight, and non-transactional installation.

The most valuable work is not a broad rewrite. It is a short hardening pass around boundaries where process lifetime, disk durability, thread ownership, and user confirmation currently disagree.

Recommended implementation sequence

Close exposed and destructive boundaries

Bind every offline Minecraft listener to loopback. Add arena site validation, exact bounds, occupancy checks, safe evacuation, and a one-time destructive confirmation.

Exit: remote joins fail and unconfirmed builds mutate nothing.

Make state transitions durable and deadlock-free

Remove the hello-path lock inversion. Journal accepted actions and arena preparation before their first irreversible effect. Align terminal replay retention.

Exit: crash injection and reconnect interleavings recover cleanly.

Harden providers and installation

Own child-process error events, bound pagination and remote bodies, make installation transactional, and make packaging instructions match the shipped files.

Exit: provider faults cannot terminate or wedge the coordinator.

Cut steady-state cost

Rotate traces, batch diagnostic writes, reduce observation copies, avoid repeated goal verification, and replace full dependency scans with a coarse change detector.

Exit: unchanged play has near-zero avoidable disk and allocation churn.

Repair product contracts and UX

Unify limits and service tiers, return explicit permission results, add cancel and in-flight states, fix accessibility, and remove or complete advertised capabilities.

Exit: every visible action reaches a clear success, rejection, or recovery state.

Full gap register

Priority means ordering, not effort. P0 blocks the next release. P1 should follow immediately. P2 belongs in the planned backlog. Open each group for evidence and the smallest useful fix.

Reliability and concurrency · 12

  1. Coordinator reconnect can deadlock the Minecraft server P0

    The socket hello path holds publicationLock then requests the synchronized registry. Server lifecycle paths hold the registry then enter publication.

    MultiplexedServerBridge.java:917,946-956, AgentRegistry.java:241-246,533-566. Prepare handshake state on the server thread, then publish an immutable batch.

  2. A hard server crash can duplicate accepted world actions P0

    Acceptance and replay ledgers are process-local. A crash after effect but before result loses the terminal outcome and allows a non-idempotent retry.

    MultiplexedServerBridge.java:1608-1613,1771-1783, ProgramActionLedger.java:15-18, AgentSavedData.java:60-81. Add a bounded write-ahead action journal.

  3. Arena build and activation ownership disappears across crashes P0

    Preparation is in memory until the run becomes active. Partial terrain edits and summoned contestants can survive without a durable owner or cleanup retry.

    ScenarioRuntimeService.java:112-128,542-647,782-792,1074-1171. Persist a preparation journal before the first block edit.

  4. Terminal replay retention disagrees across Node and Java P1

    Node evicts from a global cap while Java retains per agent, and a secondary Node set grows without a matching bound. A legitimate replay can become a duplicate error after eviction.

    protocol-v2.mjs:79-80,850-916, TerminalResultLedger.java:20-45,106-115. Define one retention model and make replay proof idempotent after eviction.

  5. Provider stdio errors can escape as uncaught EPIPE P1

    Child process streams are written without persistent error ownership. Provider exit timing can terminate the coordinator rather than reject one request.

    acp-transport.mjs:87-117,173, codex-app-server.mjs:268-304,372-379. Attach lifecycle error listeners and settle pending work once.

  6. A never-settling TTS provider can consume capacity forever P1

    Timeout aborts the signal, but capacity is released only when the raw provider promise settles. A provider that ignores abort permanently occupies a slot.

    voice-http-server.mjs:158-194,272-278,339-357. Race the provider with a server-owned terminal timeout and release exactly once.

  7. Unsupported atomic moves can block all future scenarios P1

    Result persistence treats a permanent filesystem capability failure as transient, retries every second forever, and retains pendingResult.

    MatchResultWriter.java:186-208, ScenarioResultPersistence.java:26-50, ScenarioRuntimeService.java:973-989. Detect capability once and use a documented fallback or actionable terminal state.

  8. Scenario jobs retain stale player session objects P2

    Disconnect and reconnect during build can send updates or teleport a removed ServerPlayer instance.

    ScenarioRuntimeService.java:557-646,782-800,1408-1462. Store UUID and resolve the live session at each use.

  9. Fast reconnect can permanently desynchronize spectator deltas P2

    The server may retain the UUID baseline while the client clears its base, causing every later chained delta to be rejected.

    AgentControlSync.java:143-182, ArenaSpectatorState.java:22-39,51-59. Clear on disconnect or add full-resync request and acknowledgement.

  10. Windows provider termination has no hard outer deadline P2

    The timeout starts after awaiting taskkill, so a hung OS helper can stall shutdown indefinitely.

    child-process-lifecycle.mjs:24-37. Put the complete termination sequence behind one deadline.

  11. Recovery relocates agents to chunk centers P2

    Only dimension, chunk, and integer Y survive restart. Agents can move roughly 11 blocks, leave a work site, change floors, and lose rotation.

    AgentEntityLocation.java:6-21, CodexAgentManager.java:969-1056,1314-1324. Persist bounded exact position and view with safe fallback migration.

  12. Terminal results and build publications never expire P2

    Late joiners can receive an old result popup and terminal deltas continue indefinitely.

    ArenaSpectatorSnapshot.java:94-102, AgentControlSync.java:143-182, AgentControlClient.java:281-288. Add a bounded retention window or recipient acknowledgement.

Security model reviewed

Protected assets

  • World and arena integrity
  • Agent lifecycle, goals, provenance, and results
  • Bridge and voice secrets
  • Provider login and API credentials
  • Coordinator code, configuration, traces, and bundles

Trust boundaries

  • Minecraft client to server
  • Server to local coordinator
  • Coordinator to external providers
  • Model output to authorized world action
  • Voice addon to local worker
  • Packaged bundle to installed runtime

One confirmed security finding: offline Minecraft gameplay sockets are not loopback-bound. Bridge and voice services were cleared for remote exposure because they bind locally and authenticate messages. Privileged controls are operator-gated, archives and NBT are bounded, model text is treated as untrusted, voice consent is enforced, and provider processes do not inherit unrelated credentials.

Controls worth preserving

  • Bounded server task queues and tick-start draining
  • Directional schemas and authenticated bridge traffic
  • Loopback, signed voice worker requests, and session consent
  • Archive containment, file count, size, and NBT bounds
  • Spatial scan cache, inventory arrays, tag cache, and pathfinding budgets
  • Protocol backpressure and bounded observation queues
  • Coordinator last-known-good rollback and runtime transaction support
  • Bundle, wrapper, and Carpet integrity checks
  • Result I/O stays off the Minecraft game thread
  • Dimension-aware recovery with bounded safe-position fallback
  • Strong focus versus selection visuals and keyboard roster navigation
  • Identity is not conveyed by color alone

Decisions and open questions

  • Choose a product policy for result durability on filesystems without atomic rename. Infinite retries should end either way.
  • Confirm Simple Voice Chat callback-thread guarantees. If callbacks are off-thread, resolve all Minecraft objects through server.execute.
  • Decide whether normal-agent auto-respawn is an intentional exception or a contract bug.
  • Decide whether legacy v1 control still earns its separate security and lifecycle surface.
