Agent POV spectating and takeover

Arena Agents (Fabric, Minecraft 26.1.2) · Plan written 2026-10-06 · Implemented on branch codex/agent-pov-and-claude-provider; awaiting live client QA

This plan covers two operator features: /spectator <agent> (see exactly what an agent sees, including its HUD, screens and death) and /takeover <agent> (your inputs drive the agent's body while its model is paused). It also records the small goal-system change you asked for. It is based on six parallel investigations of the vanilla 26.1.2 bytecode, Carpet, and the mod's own code; file references are to the current working tree.

Goal

  • Spectator: from an operator's chat, /spectator <agent> switches the view to the agent's first-person camera and shows the agent's hotbar, selected slot, hearts, food, armor, air, XP, effects, crosshair, open container screens and death screen. The operator's own body stays where it is. /spectator exit returns.
  • Takeover: /takeover <agent> does the same and also routes WASD, mouse look, jump, sneak, sprint, attack, use, hotbar, drop, swap, inventory and container clicks to the agent. The agent's LLM control is paused and resumes on exit. The operator's own body stays in the world and vulnerable; if it loses 2 hearts (4 HP, health plus absorption) during the takeover, the takeover ends at once. /takeover exit ends it manually.
  • Operator permission (vanilla game-master level, the same gate as every other /codex mutation) is required for both.

What the investigation found

These facts shaped the design. Each was checked against bytecode or source, not assumed.

  1. Vanilla spectating cannot be reused. ServerPlayer.setCamera teleports your body to the target and ServerPlayer.tick snaps it there every tick; sneaking exits. That is exactly what you see today, and it breaks "my body stays there". The camera must be switched by our client mod, with the server streaming the agent's state.
  2. The vanilla HUD already reads the camera entity for the hotbar, hearts, armor and air (Gui.getCameraPlayer()), but food, XP, effects, the real selected slot and hotbar slots 1 to 8 are never sent to other clients for a remote player, and several HUD gates check your game mode. So the HUD needs a data feed from the server plus a few targeted client mixins.
  3. A vanilla client cannot hold chunks around two places. Its chunk storage is one square around a single centre. A "union view" (your body plus the agent) is impossible. The workable approach is to move your chunk and entity tracking to the agent while your body's chunk stays loaded by its own server ticket, so the body remains simulated and vulnerable.
  4. The agent's body already runs real vanilla server physics. Carpet applies forward/strafe, look, sneak, sprint, jump and use through the normal LivingEntity.travel path, so walking, water, ladders, edges, mining progress, eating, bows and block placement will feel right. Two gaps matter: the current attack path only breaks blocks (a held attack never hits entities), and the shared input sink resets mining when any other input changes.
  5. The mod already has the pieces for input ownership and pausing. LeasedServerInputController arbitrates input by priority; skit mode has a reservation gate (requireNormalControlAllowed) that blocks normal control; stop/resume already cancels the running LLM turn and in-flight actions on both the Java and coordinator sides.
  6. Operator damage can be observed without a mixin using Fabric's bundled ServerLivingEntityEvents.ALLOW_DAMAGE/AFTER_DAMAGE.
  7. No naming collisions: vanilla has /spectate but no /spectator or /takeover; Carpet registers neither. Internally, "spectator" already means the public arena view (ArenaSpectatorState etc.), so new classes use the name Pov.

Commands and behaviour

CommandEffect
/spectator <agent>Starts a read-only POV session. Several operators may spectate the same agent.
/spectator exitEnds your POV session.
/takeover <agent>Starts a takeover. Exclusive per agent. Pauses the model (if the agent was active), takes an OPERATOR input lease.
/takeover exitEnds the takeover, releases the body, resumes the model.
/codex spectate|takeover <agent>Aliases so the in-game console can keep its "codex op" command pattern.
  • Agents are addressed as everywhere else: name, short id or UUID (agentArgument()). The literal exit wins over an agent literally named "exit"; that agent stays reachable by id.
  • Automatic exits: operator disconnects, dies, is teleported or changes dimension, loses operator permission; agent removed, agent changes dimension; server stops; a skit or scenario claims the agent; another operator takes over the same agent (rejected by default, see decisions).
  • Takeover-only automatic exit: the operator's body loses 4.0 HP or more in total (health plus absorption) since the takeover began, or the body dies.
  • An "Exit agent view" keybind (default unbound, in the existing Arena Agents key category) sends the exit command, so you are never stuck in a screen.
  • Chat still works during both modes so you can type the exit command.

Server design

Session runtime

  • server/pov/PovSessionRuntime: per-server map like SkitModeRuntime; sessions keyed by operator UUID with an index of agent to takeover owner. Ticked from CodexAgentServerRuntime.endTick after the bridge and before AgentInputRuntime.tick; released on server stop before the manager; hooked to player disconnect.
  • PovSession: operator, agent id, mode, state before takeover, resume-on-exit flag, input lease, accumulated body damage, start snapshot for the summary, last published revision.
  • The agent's ServerPlayer is re-resolved every tick by identity (never cached), because connected respawns replace the object.

Pausing the model (takeover)

Reuse stop/resume; do not add a lifecycle state (it would ripple through the coordinator enum, codecs and protocol). Add a transient AgentControlReservations gate that generalises skit mode's exclusivity and is checked by start, steer, resume, queue, skit play/place and the conversation router (which today can auto-resume a paused agent on speech).

  • Backstop: if a reserved agent ever becomes active, the next session tick stops it again.
  • After resume, the model gets one short conversation event (existing PLAYER_STEER kind, max 512 chars): "An operator controlled your body for 42 s: moved 37 blocks, health 20 to 14, +3 oak_log, died once." A dedicated protocol field can replace this later.
  • Conversation-only turns for PAUSED agents are suppressed while reserved, so the agent does not chat while possessed.

Seeing the agent's surroundings

  • Two @ModifyExpressionValue mixins in ChunkMap: in updateChunkTracking replace player.chunkPosition() with the agent's, and in TrackedEntity.updatePlayer replace player.position() with the agent's, for operators in a session in the same dimension. Same redirect in PlayerChunkSender.sendNextChunks so nearest chunks arrive first. Vanilla then sends the cache-centre packet and chunk diffs itself.
  • Call chunkSource.move(operator) whenever the agent changes chunk section so entity visibility is re-evaluated immediately.
  • The body's chunk ticket uses the body's real position, so the body's area stays loaded and ticking server-side.
  • Sounds and particles are broadcast around the body's position in vanilla (PlayerList.broadcast, ServerLevel.sendParticles, block cracks). One wrap each uses the agent's position for session operators so you hear what the agent hears.
  • v1 limitation: when the agent changes dimension the session ends with a message. Cross-dimension viewing would need a client level switch.

Publishing the agent's state

  • Clientbound AgentPovStatePayload, sectioned with a bitmask and revision, following the FULL/DELTA style of the arena spectator snapshots. Sections: header (session id, mode, agent UUID, entity id hint, dimension), pose (yaw, pitch, every tick), vitals (health, max, absorption, armor, food, saturation, air, XP, attack strength, game mode, flags), inventory (selected slot, 9 hotbar, offhand, 4 armor stacks with heavy components stripped), effects, open menu descriptor, death state and message. Typical 150 to 400 bytes; sent only on change except pose.
  • Clientbound AgentPovMenuPayload for container contents (slots, carried stack, data slots) whenever the agent's menu changes.
  • Item diffing must use ItemStack.matches; stacks have no value equality.

Applying operator input (takeover)

  • New InputOwner.OPERATOR at priority 1000 (above INTERACTION 300). The session holds the lease and re-acquires it when any lifecycle event clears leases (death capture, respawn, transitions), the same way ServerActionExecutor handles stale leases.
  • Continuous input (forward, strafe, jump, sneak, sprint, use held, attack held for mining, yaw, pitch, slot) arrives in OperatorInputPayload every client tick and goes through the existing lease controller into AgentInputState. If packets stop, the existing 40-tick deadman neutralises the body.
  • One-shot actions (OperatorActionPayload): attack click, drop, drop stack, swap hands, pick block, container click/button/close, open inventory, respawn. Attack clicks raycast server-side and hit entities once per click with vanilla cooldown; a held attack only mines. Drop/swap/pick relay the matching vanilla handlers on the agent's own connection so vanilla validation runs against the agent.
  • Two bug-level fixes to the shared sink: changing one input must not stopAll() (today releasing jump aborts mining), and sneak must win over sprint. These also improve model control and will be covered by the existing input tests.
  • Known Carpet gotchas to verify at runtime: fake players report hasClientLoaded() false for about 60 ticks after spawn or respawn (call handleAcceptPlayerLoad on session start), and awaitingPositionFromClient may stay set after a teleport and silently block use-on-block (clear it through an accessor).

Safety and exit

  • Body damage: ALLOW_DAMAGE records health plus absorption, AFTER_DAMAGE adds the drop to the session total; at 4.0 or more, or on body death, the takeover exits before the next tick.
  • Exit order: release the lease and send one all-released input frame, close the agent's mirrored menu, restore the lifecycle (resume), send the summary note, stop view redirection, send the stop payload, then resync the operator's own client (position re-send so the client copy of the body snaps back to the server position; chunk centre returns to the body automatically).
  • Creative operators never take damage, so the 4 HP rule is inert for them; the session badge says so.

Client design

  • client/pov/PovClient state machine: NONE, ACTIVE(mode, agent UUID, session id), SIGNAL_LOST. The server owns entry and exit through payloads; client-initiated exits send the exit command so permission checks stay server-side.
  • Camera: Minecraft.setCameraEntity(agentRemotePlayer) directly, re-bound by UUID every tick (survives respawn and re-tracking), first person forced, eye height seeded through the existing CameraEyeHeightAccessor. Vanilla then hides the agent's own body, aligns the crosshair and block outline with what the agent looks at, and handles sneak and swim eye height. When the agent entity is missing (dead and removed, out of tracking), fall back to the marker-entity technique from CameraDirectorClient at the last pose with a "signal lost" badge. Director playback is stopped on entry and refused while active; SpectatorCameraAssistant already disables itself when the camera is not the local player.
  • Rotation: a small mixin on the agent's view yaw/pitch returns the exact float from the payload (spectating) or the local predicted look (takeover), so the view is not quantised to packet precision and mouse look has no round-trip lag.
  • HUD: an unregistered stand-in RemotePlayer (never added to the level) is filled from the payload: inventory, selected slot, food, XP, health, absorption, air, armor attribute, effects. Gui.getCameraPlayer() returns this stand-in, so vanilla draws the agent's hotbar, hearts, food, armor and air unchanged. Small wraps fix the remaining reads of the local player: game-mode gates (getPlayerMode, canHurtPlayer, hasExperience), XP level and bar, effects, the attack indicator and the held-item name. Your own player object is never modified, which is why exit needs no resync of the client HUD.
  • Session badge: one small element attached after the hotbar via Fabric's HudElementRegistry: agent name, mode, and in takeover your own body's HP against the 4 HP exit threshold, flashing when the body takes damage. This is session-scoped, not a persistent world overlay, so it respects the existing "no persistent HUD" rule.
  • Input capture (both modes keep your body still): KeyboardInput.tick TAIL copies then zeroes key presses and the move vector (no movement, no input packet); Minecraft.handleKeybinds HEAD drains hotbar, drop, swap, inventory, attack, use and pick clicks; startAttack, continueAttack, startUseItem and pickBlockOrEntity are cancelled while active; MouseHandler.turnPlayer feeds the predicted look instead of your body; hotbar scroll is captured. Spectating discards the captured input; takeover sends it every tick.
  • Screens: container screens are built from the mirrored menu type and the stand-in's inventory, filled from AgentPovMenuPayload, and never touch LocalPlayer.containerMenu or vanilla container packets (container id 0 would otherwise overwrite your own inventory). Spectating blocks clicks; takeover sends click/button/close actions. The player inventory (E) is a mirrored inventory screen for the agent.
  • Death: a custom AgentPovDeathScreen with the vanilla look, the death cause, and buttons: Respawn (takeover only, routed through the manager's verified respawn path, never a raw respawn packet) and Leave. Spectators see "Waiting for respawn". It closes when the agent is alive again.
  • v1 hides first-person hands. Rendering the agent's arm and held item is a later polish item.

Decisions already made

Client-side camera switch, not vanilla spectating
Vanilla moves the body; ours cannot.
Chunk and entity tracking follow the agent; the body stays loaded by its own ticket
A union view is impossible on a vanilla client. Your own surroundings stop rendering while you are in POV; nothing about the body changes server-side.
HUD from a stand-in player, not by mirroring the agent's packets into your player
Mirroring would fight the server's own health/XP/inventory packets, could corrupt your client inventory (container id 0), and would hide your own body's health. The stand-in makes exit free.
Reuse stop/resume plus a reservation gate, no new lifecycle state
Keeps the coordinator protocol untouched.
Operator input rides the existing lease system
Model leases lose arbitration automatically; one-shot actions bypass the sink.
Internal name Pov, commands /spectator and /takeover
"Spectator" is taken internally by the arena view; the commands keep your wording.

  3. Agent death during takeover with an automatic respawn policy: show the death screen and wait for your Respawn click (recommended) or let the policy respawn it on its own?

  5. Creative operators: allow takeover with the damage rule inert (recommended) or require survival/adventure?

  8. Goal-translation forcing: confirm Luna for Codex and Sonnet 5.5 for Claude, with the agent's own reasoning effort kept where supported.
