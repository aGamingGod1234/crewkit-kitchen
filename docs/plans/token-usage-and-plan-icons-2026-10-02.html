Small real-model check

GPT-6.1 Sol was given two fixed factual scenarios before and after the representation change. All four runs used valid native observe and say calls and correctly returned exact coordinates, identifiers, counts, urgent health facts and unknown values. Both after runs received the compact format.

Reported uncached input across the two scenarios fell from 33,193 to 24,476 tokens, a 26.3% reduction in this small controlled sample. Across all four runs, reported input was 298,949, including 241,280 cached, with 374 output tokens. These checks used the existing subscription and changed no Minecraft state. Two pairs cannot establish general task quality, latency, or weekly usage savings.

Decisions and limits

The runtime keeps its authoritative observations and existing game executor. Formatting does not select targets, batch actions, suppress danger or control the player. The agent remains the decision maker. Default replies do not depend on previous replies for decoding. Context summaries, fact dropping and arbitrary observation caps are outside this implementation.

The existing cache hit rate is already high. The compact prefix and replies address repeated input while preserving the stable thread and tool order. A growing conversation can still produce large cumulative cached totals; these changes do not promise a fixed reduction in the weekly allowance.

The icon bridge and pinned Minecraft APIs passed local checks, including 30 bridge checks. Actual GPU output, resource-pack appearance and installed Desktop behavior remain unverified. Audible speech was not tested.
