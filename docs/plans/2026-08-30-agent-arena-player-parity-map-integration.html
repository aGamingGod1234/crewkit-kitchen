Agent Arena implementation plan

Player parity and real map integration

Turn the current fake-player runtime into a reliable Minecraft player controller, connect imported arena modules to live matches, and replace technical block layouts with one polished PvP arena and one sixteen-stage parkour course.

Goal

Agents should complete the same meaningful Survival, Adventure, and Creative gameplay tasks as human players. Models choose goals, strategy, targets, and short control segments. Deterministic controllers execute time-sensitive movement and combat at Minecraft tick rate.

Scope

Included

Scenario rules, arena manifests, module integration, player control, menu gestures, fresh observations, permissions, resets, and real multi-agent verification.

Deferred

Rare workstations, complete vehicle support, advanced elytra play, editable books and signs, arbitrary modded menus, and more than one polished map per core category.

Excluded

Client settings, resource-pack prompts, operator-only commands, raw packet control, downloaded command blocks, unknown datapacks, imported entities, and custom loot NBT.

Implementation sequence

01

Make each arena a real game

  • Enforce configured match duration.
  • Apply directed events to the world or remove unsupported copy.
  • Award scores from server evidence and persist the audit trail.
  • Finish matches from authoritative rules, not agent claims.
Exit checkEach category completes one deterministic headless match with earned scores, applied events, and a durable result.
02

Connect arena modules to production

  • Add a versioned arena manifest for module paths, transforms, offsets, spawns, objectives, and spectator positions.
  • Route launch through the loader, composer, safety policy, and reset job.
  • Make spawning and match results consume composed anchors and hashes.
  • Keep the procedural builder as a temporary fallback.
Exit checkOne project-owned fixture launches through the production module path at 1, 2, 4, 8, and 16 players, then resets twice without residue.
03

Add the player control contract

  • Define one canonical capability manifest shared by Java, coordinator schemas, documentation, and simulator checks.
  • Add bounded control segments containing movement, look, held inputs, pulses, hotbar slot, and hand.
  • Keep moveTo and existing semantic actions as compatibility adapters.
  • Add input lease expiry, guaranteed neutralization, out-of-band cancellation, and tick-based deadlines.
  • Fix offhand application, block protection, door reach, melee range, and item-use postconditions.
Exit checkTimed jump, strafe attack, crouch placement, offhand shield, cancellation, death, disconnect, and lease-expiry tests all pass through a real fake player.
04

Make observation and menus reliable

  • Make observe request and await a newer event sequence.
  • Page dense observations by section and cursor instead of replacing them with a truncation sentinel.
  • Add collision, fluid, climbable, equipment, velocity, pose, vehicle, projectile, block-state, and exact ray-target facts.
  • Replace menu one-offs with state-fenced click, button, recipe, text, and close gestures.
Exit checkA repeated-block parkour fixture reconstructs without data loss, post-action facts are fresh, and delayed clicks cannot affect a newer menu.
05

Ship one PvP arena and one parkour curriculum

  • Resolve BizCub permission evidence or choose another source before tracking geometry.
  • Curate spawn, camera, goal, hazard, and connection anchors for the selected PvP arena.
  • Rebuild cages, hazards, resets, and scoring as server-owned mechanics.
  • Create sixteen ordered parkour stages with a route descriptor for checkpoint order, lane ownership, jump mechanics, and difficulty.
  • Use Parkour Masters only as a design reference unless its license gate is resolved.
Exit checkHuman review approves PvP sightlines and parkour readability. Automated runs prove spawns, routes, checkpoints, completion, and reset at supported roster sizes.
06

Contain agents and prove sixteen-player operation

  • Restrict arena agents to allowed match regions and normal vanilla permissions.
  • Give provider subprocesses an allowlisted environment.
  • Reserve cancellation and hazard capacity in the coordinator and bridge queues.
  • Feed measured Minecraft tick pressure into adaptive admission.
  • Run real headless trials at 1, 4, 8, and 16 agents.
Exit checkA 30-minute sixteen-agent run holds at least 19.5 TPS, keeps tick p95 at or below 50 ms, and ends with no stale inputs, actions, queues, processes, or false completions.

Decisions that should not drift

  • Player parity means gameplay outcomes available to a normal server player. It does not include client settings or operator powers.
  • The model chooses strategy and short intent segments. Deterministic controllers handle 20 Hz timing.
  • The model-facing interface converges on observe, moveTo, control, menu, say, and finish.
  • Imported maps contribute reviewed geometry only. The mod owns scoring, events, loot, checkpoints, resets, and completion.
  • Protocol changes use a locked coordinator and mod pair or a versioned migration. Protocol v2 semantics do not change silently.
  • Licensing, immutable hashes, safe extraction, DataFixer upgrades, and block-only conversion stay mandatory.

Main risks

  • Concurrent worktree changes can invalidate baselines. Start implementation only after active local work is isolated.
  • Short control segments can create excessive model traffic. Batch frames and retain long-distance navigation.
  • Parkour cannot use the existing walk-only reachability check. It needs a transition model for jumps, climbs, water, slime, and falls.
  • Detailed geometry will still feel empty if scoring and world events remain metadata.
  • A platform license label alone does not satisfy the repository's retained-permission policy.
  • Sixteen-agent confidence requires real Minecraft bodies and provider processes, not replay or simulator-only soaks.
