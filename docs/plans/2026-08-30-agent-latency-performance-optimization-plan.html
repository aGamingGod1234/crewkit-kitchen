Agent Arena / implementation plan / 30 Aug 2026

Cut the time between intent and action.

Reduce cold startup, provider wait, observation churn, action admission, and speech delay. The target is a measured 2x improvement where the application controls the latency, without changing the selected model profile or weakening factual action checks.

Scope

  • Coordinator startup, agent creation, warm session reuse, planning, retries, and urgent attention.
  • Observation capture, semantic deduplication, prompt projection, ArenaScript watchers, protocol encoding, and queueing.
  • Minecraft action admission, navigation, combat, post-action facts, and restore or respawn work.
  • Microphone endpointing, STT admission, TTS generation, caching, streaming, and first audible packet.
  • A fair real headless A/B run with identical concurrency and instrumentation in both arms.

Work sequence

  1. Establish honest phase timing

    • Separate startup, queue wait, provider time, parse, dispatch, Minecraft acceptance, first displacement, completion, STT, first PCM byte, and first outbound voice packet.
    • Fix the A/B defaults so both arms use identical planning concurrency. Measure trace overhead with tracing on and off.
    • Record cold and warm results separately. Keep failures and timeouts in the report.

  2. Stop redundant observations and model wakes

    • Do not build full observations at 20 Hz for idle, paused, completed, or error agents.
    • Use semantic thresholds for movement, velocity, fall progress, air, and action-owned inventory churn.
    • Apply cheap distance and view-cone filters before raycasts. Reuse visibility and world-cell work within one tick.
    • Budget native and ArenaScript input by factual priority, with explicit omitted counts.

  3. Shrink the provider hot path

    • Return exact existing sessions before catalog discovery.
    • Install the planner contract once. Warm turns send authoritative state deltas and a short invariant reminder.
    • Keep provider continuation after local parse errors and send only bounded correction details.
    • Make the output schema reject invalid directive and source combinations before generation completes.

  4. Make urgent work actually urgent

    • Let damage, conversation, and other priority escalations interrupt stale ordinary thinking.
    • Make ACP cancellation settle promptly. Replace an unresponsive transport after a short grace period.
    • Bound each agent event queue and coalesce only safe consecutive observations.
    • Keep bounded pending capacity for goal translation even when all 16 agents are active.

  5. Remove cold-start floors

    • Launch the owned bundled coordinator immediately after bridge bind. Keep the 3-second grace only for explicit external coordinators.
    • Cache runtime fingerprints, Node identity, Codex executable discovery, catalog state, and unchanged workspace templates.
    • Bound prewarm fanout and allow real goals to preempt queued prewarm work.
    • Publish provisional readiness for the configured exact profile while full catalog discovery continues in the background.

  6. Start and continue actions sooner

    • Admit actions and apply input at the start of a server tick. Keep result and observation publication at the end.
    • Reserve queue capacity for actions and cancellation while preserving per-agent ordering.
    • Attach authoritative post-action facts to terminal results so sequential actions avoid an extra observation exchange.
    • Expose bounded sustained combat and pursuit using exact observed target IDs.

  7. Reduce tick and coordinator CPU

    • Encode each outbound observation once, reuse its bytes for sizing and writing, and flush bounded batches.
    • Stop deep-copying the same trusted normalized payload at every internal boundary.
    • Brand fully validated immutable ArenaScript facts privately, then reuse them across watcher checks.
    • Cache navigation cells per tick and add replan hysteresis for moving targets.

  8. Cut speech response time

    • Replace the fixed 300 ms endpoint delay with adaptive local voice activity detection.
    • Reserve STT admission and use weighted scheduling so TTS cannot reject player speech.
    • Singleflight identical TTS misses. Separate STT and TTS worker failure domains.
    • Stream PCM through Node and Java into bounded playback queues. Keep cancellation and consent checks at every ownership boundary.

  9. Prove the result in the real path

    • Run paired baseline and optimized builds against the same headless Fabric world, provider profile, prompt, concurrency, timeout, seed, and instrumentation.
    • Use at least 10 paired repetitions per primary cell. Treat p95 and p99 as provisional below 30 samples.
    • Test direct messages, movement, mining, combat, speech, death, restore, and 16-agent mixed load.

Decisions and limits

  • Keep planning concurrency at 16 for the main comparison. The earlier 16-to-4 reduction made load-16 completion roughly three times slower.
  • Do not silently lower the user-selected reasoning effort or service tier.
  • Do not run Minecraft world reads or mutations on background threads.
  • Do not cache model decisions, race duplicate model calls, or dispatch partial unvalidated output.
  • Do not claim 2x from simulator timing alone. The release claim needs the real headless path.

Risks

  • Missed attention. Semantic observation suppression needs explicit hazard, target, inventory, conversation, and action-result tests.
  • Ordering bugs. Priority lanes and start-tick admission must retain action-before-cancel and result-before-post-action-facts rules.
  • Voice privacy. Consent revocation must cancel owned microphone work even if TTS cancellation becomes less destructive.
  • Misleading wins. Provider variance, unequal concurrency, setup cost, and trace overhead can fake an improvement unless the paired experiment controls them.
Source: repository-wide read-only audit by ten reviewers. The audit found opportunities but did not implement performance changes.
