# Reuse post-action observations for native action handoff

This is a **local experiment**, not a demonstrated whole-task speedup. The selected model still authors all actions. The runtime now accepts the server's post-result observation as the fresh fact sample for a camera sweep step, program continuation, or post-action feedback. It races the existing explicit observation request as a fallback, preserves goal/lifecycle checks, and continues only after an authoritative sample. The server already publishes an attention observation after an action result, so the previous unconditional wait for a requested sample could add one server tick before the next authored action.

## Before and after

The baseline is experiment commit `94072179` (runtime SHA-256 prefix `f7f892565dd05b12`); the changed runtime SHA-256 prefix is `c7e201d22b40adf6`. Both use the same Minecraft mod, fixed `Get 1 oak log` arena, Codex `gpt-6-sol`/low/priority profile, and coordinator configuration. The change is in `coordinator/src/native-tool-runtime.mjs`; no server or model prompt changed.

Four headless Minecraft runs per arm all passed. Protocol audits show 24 camera-sweep completion-to-next-action gaps in the baseline and 30 in the changed arm. Their nearest-rank p50 fell from **103 ms to 50 ms** (51% lower), and p95 from **112 ms to 71 ms** (37% lower). Different runs had different model decisions and action counts, so the gap samples are not matched authored sequences. Inspection requests were still sent in these live runs; the benefit was continuing on the arriving server publication instead of waiting for the request response.

| In-game fixed arena | Baseline | Changed |
| --- | ---: | ---: |
| Passed runs | 4/4 | 4/4 |
| Whole-task p50, nearest rank | 25.551 s | 29.814 s |
| Whole-task p95, nearest rank | 31.926 s | 42.343 s |
| Camera-sweep gap p50 | 103 ms (24 gaps) | 50 ms (30 gaps) |
| Camera-sweep gap p95 | 112 ms | 71 ms |

The whole-task result was **worse** in this small live sample. Each run let the model choose actions independently, and the changed arm had 12–16 completed actions versus 8–13 in the baseline. This comparison establishes a shorter observed camera handoff, not faster task completion. It does not exercise `runProgram` live.

A 50 ms tick-quantized bridge model used the real native runtime and ArenaScript with **40 repetitions per arm per workload**. It alternated arm order; all authored action hashes matched, and every paired duration was shorter in the changed arm. This model excludes provider inference, networking, and real Minecraft physics.

| Tick-model workload | Baseline p50 | Changed p50 | Baseline p95 | Changed p95 |
| --- | ---: | ---: | ---: | ---: |
| Eight-step `lookAround` | 1,199.737 ms | 799.165 ms | 1,204.481 ms | 812.119 ms |
| Four-action `runProgram` | 598.034 ms | 403.302 ms | 610.065 ms | 409.349 ms |
| `navigate` with post-action facts | 346.291 ms | 298.216 ms | 360.792 ms | 312.602 ms |

The tick-model action-handoff p50 was 47.350 → 0.330 ms for `lookAround` and 47.814 → 0.543 ms for `runProgram`. The changed arm used the pushed publication for all modeled samples, so explicit requests fell from 320 → 0 for `lookAround`, 160 → 0 for `runProgram`, and 40 → 0 for `navigate`. Real Minecraft did not eliminate those requests, which is why the model is evidence of the mechanism rather than a live throughput estimate.

## Verification and evidence

`npm test` from `coordinator/` passed: **1,777 passed, 3 skipped, 0 failed** (1,780 total). The five added runtime tests cover early publication, post-result freshness, fallback on missing publication, disposal of a superseded request, and program continuation. `git diff --check` passed. No Java source changed. The after runtime was restored following the baseline run and its SHA-256 prefix rechecked.

Local raw artifacts are under `runtime/speed-arms/`: `balanced-analysis.json`, `native-tick-40.json`, `coordinator-test.out`, and `arms.log`. The eight headless runs and their protocol audits are under `runtime/headless-runs/`; `arms.log` maps each run ID to an arm. The live summary was generated by `node coordinator/src/benchmark/live-action-gaps.mjs <arm>=<scenario-directory> ...`. The tick model was run with `node coordinator/src/benchmark/native-tick-handoff.mjs coordinator/src/.bench-before-runtime.mjs coordinator/src/.bench-after-runtime.mjs 40 50`, using runtime snapshots copied beside `native-tool-runtime.mjs` so its relative imports resolve.

The experiment remains local and unmerged. A valid live `runProgram` trial and a larger matched task set are needed before claiming broader gameplay speed gains. Model decision time and action choice still dominate whole-task variability.
